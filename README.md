# console

نطاق مستقل (`console.hostaka.fun`) — لوحة تحكم هوستاكا + صفحة تعريفية
بالمشروع ودور المساهمة فيه. المكان اللي كانت فيه لوحة `/admin` بالموقع
الرئيسي قبل، انتقلت هنا بالكامل.

## البنية

نفس نمط `orbithub` و`aethercast` بالضبط — سيرفر Express حقيقي + بروكسي
شفاف لـ `/api/*`:

```
console/
├── server.js
├── package.json
├── vercel.json
├── .env.example
└── public/
    ├── index.html / index-landing.js / index-landing.css   ← الصفحة الرئيسية (تعريفية)
    ├── console.html / console.js / console.css              ← اللوحة الفعلية (/user/console)
    ├── theme.css / shared.css / shared.js
    ├── emoji.css / emoji.js / emoji-catalog.json
    ├── i18n.js / modal.js / protect.js
    ├── translations/ar.json / en.json
    └── console-icon.png
```

كل صلاحيات الأدمن ومنطق قاعدة البيانات يبقى بالكامل على السيرفر
الرئيسي (`hostaka.fun`) — كل نقاط `/api/admin/*` **لم تتغيّر إطلاقاً**،
فقط الواجهة انتقلت لمستودع مستقل.

## المسارات

- **`/`** — صفحة تعريفية عامة (قابلة للفهرسة): شرح مختصر عن دور
  console بمنظومة هوستاكا، مع 4 أزرار تنقّل:
  - **المنصة** → `hostaka.fun`
  - **الويكي** → `wiki.hostaka.fun`
  - **التجارب** → `laps.hostaka.fun`
  - **لوحتك** → `/user/console` (نفس النطاق)

  فيها نفس آلية مزامنة تسجيل الدخول (توكن) المستخدمة بباقي المستودعات،
  فلو المستخدم مسجّل دخول أصلاً بالمنصة، اسمه يطلع بأعلى الصفحة تلقائياً.

- **`/user/console`** — اللوحة الفعلية، محمية بالدور (role):
  - **لست مسجّل دخول** → شاشة تطلب تسجيل الدخول (توجّه لـ `hostaka.fun/login`).
  - **مسجّل دخول لكن `role !== 'admin'`** (عضو عادي، بدون أي رتبة) →
    شاشة "أوبس، لست مشرفاً! 🙂" فيها نموذج انضمام: تاريخ الميلاد،
    البريد الإلكتروني، الاسم الكامل، سبب الرغبة بالانضمام، وتفاصيل
    المساهمة المقترحة. الإرسال يحفظ الطلب كـ **بلاغ (report) من نوع
    `join_request`** عبر `/api/reports` الموجود أصلاً — يوصل لنفس لوحة
    "البلاغات والدعم" اللي الأدمن شايفها بلوحته، بدون أي تعديل على
    السيرفر.
  - **`role === 'admin'`** → اللوحة الحقيقية (نفس المحتوى القديم بالضبط:
    Dashboard، المستخدمين، المنشورات، التوثيق، الإشعارات، البلاغات،
    السجلات — كل شي زي ما كان، فقط بمكان جديد).

  حالياً الأدوار المتاحة هي `member` و`admin` فقط (زي ما طلبت)، وممكن
  تضيف أدوار ثانية مستقبلاً بنفس النظام بدون تعديل هيكلي.

## اختبار محلي

```bash
npm install
npm start
# افتح http://localhost:3000
```

## النشر على Vercel

1. مشروع Vercel جديد من هذا المستودع.
2. أضف دومين `console.hostaka.fun` من Settings → Domains.
3. أضف سجل `CNAME` باسم `console` بـ DNS حق `hostaka.fun` يشاور على
   القيمة اللي يعطيك ياها Vercel.

## متغيرات البيئة على Vercel

| المتغير | مطلوب؟ | القيمة |
|---|---|---|
| `HOSTAKA_API_BASE` | ❌ اختياري | `https://hostaka.fun` (افتراضية بالكود أصلاً) |

## آلية تمرير تسجيل الدخول بين النطاقين

نفس آلية orbithub وaethercast بالضبط — `localStorage` ما ينشارك بين
`hostaka.fun` و`console.hostaka.fun`. الحل بطرفين:

- **بالمستودع الرئيسي:** `/admin` صار يخدّم صفحة تحويل خفيفة تقرأ
  التوكن من localStorage وتحوّل المستخدم لـ
  `console.hostaka.fun/user/console` معه. **زر "لوحة التحكم" اتحذف
  بالكامل من واجهة المنصة الرئيسية** (زي ما طلبت) — الوصول للوحة صار
  فقط عبر console.hostaka.fun مباشرة (أو أي رابط قديم لـ `/admin`
  كان محفوظ، بيشتغل عبر التحويل التلقائي).
- **بهذا المستودع:** `index-landing.js` و`console.js` يلتقطون `?token=`
  أول تحميل، يخزّنونه محلياً، ويمسحونه من شريط العنوان.

**⚠️ لازم تنشر تحديث `/admin` (وحذف ملفات admin القديمة) على المشروع
الرئيسي قبل تفعيل console — وإلا ما فيه طريقة توصل للوحة إطلاقاً.**

## أمان: حذف ملفات admin القديمة من المشروع الرئيسي

بعكس `/chat`/`/video` وغيرها (اللي تركت ملفاتها القديمة كـ dead files
غير ضارة)، ملفات `admin.html/js/css` **اتحذفت فعلياً** من المشروع
الرئيسي، لأنها كانت تحتوي نظام دخول (بريد+كلمة مرور) مستقل شغّال —
تركها كانت تعني وجود مسار دخول مكرر للوحة التحكم حتى بعد الانتقال
لـ console. تأكد إن نسخة المشروع الرئيسي اللي تنشرها فعلاً محذوف منها
هالملفات الثلاثة.

## الشعار

`console-icon.png` حالياً أيقونة بسيطة مؤقتة (رمز `>_`) لحد ما توفّر
شعار console الرسمي — بس قله لي وقتها زي ما سوّينا بـ orbithub
وaethercast.
